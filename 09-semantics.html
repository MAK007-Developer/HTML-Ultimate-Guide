    09 · Semantics

    Semantic Page Layout

    The element set that gives a page a skeleton assistive tech and crawlers can actually understand.

    Full page skeleton

    <!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Acme — Product engineering</title>
</head>
<body>

  <a class="skip-link" href="#main">Skip to main content</a>

  <header>
    <a href="/" aria-label="Acme home">
      <img src="/logo.svg" alt="" width="120" height="32">
    </a>

    <nav aria-label="Primary">
      <ul>
        <li><a href="/product">Product</a></li>
        <li><a href="/pricing">Pricing</a></li>
        <li><a href="/docs" aria-current="page">Docs</a></li>
      </ul>
    </nav>
  </header>

  <main id="main" tabindex="-1">

    <article>
      <header>
        <h1>Responsive images, explained</h1>
        <p>Published <time datetime="2026-10-30">30 Oct 2026</time></p>
      </header>

      <section aria-labelledby="srcset-heading">
        <h2 id="srcset-heading">srcset and sizes</h2>
        <p>…</p>
      </section>

      <section aria-labelledby="picture-heading">
        <h2 id="picture-heading">When to use picture</h2>
        <p>…</p>
      </section>
    </article>

    <aside aria-labelledby="related-heading">
      <h2 id="related-heading">Related reading</h2>
      <ul>
        <li><a href="/docs/perf">Performance basics</a></li>
        <li><a href="/docs/a11y">Accessibility basics</a></li>
      </ul>
    </aside>

  </main>

  <footer>
    <address>
      Acme Inc.<br>
      1 Rocket Road, Springfield
    </address>
    <p><small>© 2026 Acme Inc.</small></p>
  </footer>

</body>
</html>

    Element semantics

    When to reach for each layout element
    ElementMeaningUse for
    headerIntroductory content for a page or a sectionSite banner, article header, card header.
    navMajor navigation blocksPrimary menu, breadcrumbs, pagination, in-page TOC.
    mainThe dominant content of the documentExactly one per page; skips duplicated chrome.
    articleSelf-contained, syndicatable contentBlog post, news story, forum post, comment, widget.
    sectionA thematic grouping with a headingChapters, tab panels, grouped form fields.
    asideTangentially related contentSidebar, pull quote, related links, ad slot.
    footerFooter for a page or sectionCopyright, author info, related links.
    addressContact information for its nearest article/bodyAuthor email, physical address.
    divGeneric block container, no semanticsStyling hooks when nothing more specific fits.
    spanGeneric inline container, no semanticsStyling hooks inside a sentence.

    Rules of thumb

    • Use div as a last resort. If a section really is a thematic group, use section; if it's independently syndicatable, use article; if it's just a styling hook, div is fine.
    • A section needs an accessible name — usually a heading inside it, linked via aria-labelledby, or an aria-label attribute.
    • article vs section: an article could stand alone (a blog post, a comment). A section is a chapter of the surrounding article.
    • Landmarks should be distinct. Multiple nav elements are fine if each has a different aria-label ("Primary", "Breadcrumb", "Footer").
    • Never wrap main in another main. One <main> per page.
