    Text Content

    Headings

    <h1>Page title (exactly one per page)</h1>

<h2>Major section</h2>
<h3>Subsection</h3>
<h4>Sub-subsection — never skip from h2 to h4</h4>

<!-- hgroup groups a heading with its subtitle / tagline -->
<hgroup>
  <h2>Acme Rocket 3000</h2>
  <p>The fastest way to leave the atmosphere</p>
</hgroup>
    • One h1 per page, matching the page's purpose (not necessarily the site name).
    • Never skip levels — a jump from h2 to h4 breaks screen-reader navigation.
    • Never choose a heading level for its size. Style it with CSS instead.
    • The old document outline algorithm (where nested sections generated implicit heading levels) was removed from browsers. Heading levels are now literally the numbers you write.

    Paragraphs, <br>, <hr>

    <p>A paragraph is a run of text with a single theme.</p>

<!-- <br> is a *line break within* one piece of content: -->
<p>
  221B Baker Street<br>
  London NW1 6XE<br>
  United Kingdom
</p>

<!-- <br> is NOT for spacing between paragraphs. Use margins. -->

<!-- <hr> is a thematic break (a scene change), not a decorative line -->
<p>Three years passed.</p>
<hr>
<p>She returned on a Tuesday.</p>

    Emphasis / importance

    Inline text semantics and their screen-reader impact
    ElementMeaningScreen-reader impactUse when…
    strongStrong importance, seriousness, urgencyOften announced with emphasisThe content is genuinely important.
    bStylistically offset, no extra importanceNoneKeywords in a summary, product names.
    emStress emphasis — changes sentence meaningOften announced with emphasis“I said that” vs “I said that”.
    iAlternate voice, technical term, idiomatic phraseNoneTaxonomy names, foreign words, thoughts.
    markMarked for reference in a different contextFrequently announced as “highlighted”Search-result highlighting.
    smallSide comment, fine print, legal textNoneTerms and conditions, copyright lines.
    sNo longer accurate or relevantNone“Was $49” — a struck-through old price.
    delRemoved from the documentSome readers announce “deleted”Tracked edits, changelogs.
    insAdded to the documentSome readers announce “inserted”Tracked edits, changelogs.
    uUnarticulated annotation (e.g. a spelling error)NoneRarely — it looks like a link. Avoid.
     
    <p><strong>Warning:</strong> this action cannot be undone.</p>
<p>I never said <em>that</em> — I said <em>this</em>.</p>
<p>Search results for "<mark>html</mark> guide".</p>
<p><s>$49.00</s> <strong>$29.00</strong></p>
<p><small>Prices exclude VAT.</small></p>
<p><del datetime="2026-10-01">Old sentence.</del> <ins datetime="2026-10-30">New sentence.</ins></p>

    blockquote, q, pre/code, kbd, samp, var

    <blockquote cite="https://example.com/source">
  <p>Programs must be written for people to read, and only
     incidentally for machines to execute.</p>
  <footer>— <cite>SICP</cite></footer>
</blockquote>

<!-- <q> is for short inline quotations; browsers add the quotes -->
<p>She said <q cite="https://example.com">ship it</q> and left.</p>

<!-- Preformatted, whitespace-preserving block of code -->
<pre><code>const greet = (name) =&gt; `Hello, ${name}`;</code></pre>

<!-- Keyboard input -->
<p>Press <kbd>Ctrl</kbd> + <kbd>C</kbd> to copy.</p>

<!-- Program output -->
<p>The compiler said <samp>error: expected ';'</samp>.</p>

<!-- Mathematical / programming variables -->
<p>Where <var>n</var> is the number of items.</p>

    The <time> element

    <!-- Machine-readable date -->
<time datetime="2026-10-30">30 October 2026</time>

<!-- Date + time + timezone -->
<time datetime="2026-10-30T14:00Z">2pm UTC on 30 October</time>

<!-- Time of day -->
<time datetime="09:30">half past nine</time>

<!-- Duration -->
<time datetime="PT2H30M">2 hours 30 minutes</time>

<!-- Publication / modification timestamps -->
<article>
  <header>
    <h2>Release notes</h2>
    <p>Published <time datetime="2026-10-30">30 Oct 2026</time></p>
  </header>
</article>

    sup, sub, abbr

    <p>E = mc<sup>2</sup></p>
<p>Water is H<sub>2</sub>O</p>

<!-- First use of an abbreviation: expand it in the title -->
<p><abbr title="Cascading Style Sheets">CSS</abbr> controls presentation.</p>
<p>Then just use CSS for the rest of the page.</p>

    Ruby

    <!-- Ruby annotations for East Asian pronunciation.
     <rp> provides fallback parentheses for browsers without ruby. -->
<ruby>
  漢 <rp>(</rp><rt>kan</rt><rp>)</rp>
  字 <rp>(</rp><rt>ji</rt><rp>)</rp>
</ruby>

<!-- For complex annotations use nested rtc -->
<ruby>
  漢字
  <rtc><rt>かんじ</rt></rtc>
  <rtc><rt>kanji</rt></rtc>
</ruby>

    Bidirectional text

    <!-- Direction on the whole document or a block -->
<html lang="ar" dir="rtl"> … </html>

<p dir="rtl" lang="ar">مرحبا بالعالم</p>
<p dir="ltr" lang="en">Hello world</p>

<!-- <bdi> isolates a user-supplied name so it can't scramble
     the surrounding punctuation. Essential for mixed-direction UIs. -->
<p>User <bdi>إيان</bdi> left a comment.</p>

<!-- <bdo> forces a direction override -->
<p><bdo dir="rtl">forced direction</bdo></p>
