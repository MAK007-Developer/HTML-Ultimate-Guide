    Mental Model & Fundamentals

    What HTML actually is, how an element is built, and the rules the parser will enforce whether you like it or not.

    What HTML actually is

    HTML is a markup language for describing the structure and meaning of content. It is not a programming language and not a styling language. The browser parses your markup into a DOM tree; CSS decides how that tree looks, and JavaScript decides what it does. When you write HTML you answer “what is this thing?” — a heading, a list, a navigation landmark, a form control — not “what should it look like?”.

    ✔

    The core discipline: choose the element whose meaning matches the content. Styling comes later and can make any element look like anything. Semantic HTML survives when CSS fails to load, when a screen reader reads it, and when a search engine crawls it.

    Anatomy of an element

    An element is an opening tag, optional attributes, content, and a closing tag.

    <a href="/docs" class="link" target="_blank">Read the docs</a>
 │  └────┬───┘ └───┬────┘ └──────┬──────┘ └──────┬──────┘
 │       │         │             │               └── text content
 │       │         │             └── attribute value (quoted)
 │       │         └── attribute name
 │       └── attribute name
 └── tag name

<!--  Breakdown of the five parts  -->
1. Opening tag        <a ...>
2. Attribute name     href
3. Attribute value    "/docs"
4. Content            Read the docs
5. Closing tag        </a>

    Void (self-closing) elements — the <div /> gotcha

    Only a fixed set of elements are void: they cannot have children and never take a closing tag. They are area, base, br, col, embed, hr, img, input, link, meta, source, track and wbr.

    <!-- ✅ Correct -->
<div class="card"></div>
<img src="a.png" alt="A">
<br>
<hr>

<!-- ❌ The trap: HTML does NOT support self-closing syntax -->
<div class="card" />

<!-- The above is parsed as an ordinary opening tag: -->
<div class="card">
<p>This paragraph is now INSIDE the div</p>
<!-- ...and every following sibling is swallowed by the div. -->
    !

    A trailing slash on a non-void element is simply ignored by the HTML parser. Only XML/XHTML parsers care. Always write <div></div>.

    Content models

    Every element declares which categories of content it accepts. These are the categories you need to reason about.

    HTML content categories
    ModelWhat it meansTypical membersNotes
    FlowAlmost everything that lives in the body.div, p, ul, section, img, formThe broadest category; most body content is flow content.
    PhrasingText-level content — what you'd put inside a sentence.span, a, em, strong, code, img, kbdMost phrasing content is also flow content.
    SectioningCreates an outline entry / landmark-ish region.section, article, nav, asideEach should have an accessible name (heading or aria-label).
    HeadingSection titles.h1–h6, hgroupDo not skip levels; do not use for visual size.
    EmbeddedExternal or generated content embedded in the document.img, video, audio, iframe, canvas, svgAlways supply fallbacks and accessible names.
    InteractiveContent that the user can activate or control.a[href], button, input, select, details, labelInteractive content must never nest inside interactive content.
    PalpableContent that is not hidden and has real substance.Text, img, video, input, blockquoteAn element with no palpable content may be hidden from assistive tech.

    Illegal nesting examples

    <!-- ❌ Block content inside a paragraph -->
<p>Intro text <div>a block</div> more text</p>
<!-- The parser silently closes the <p> for you: -->
<!-- <p>Intro text </p><div>a block</div> more text<p></p> -->

<!-- ❌ Interactive inside interactive -->
<a href="/settings"><button>Settings</button></a>

<!-- ❌ Nested links (the inner one is not a link at all) -->
<a href="/a">Alpha <a href="/b">Beta</a></a>

<!-- ❌ List items outside a list -->
<div><li>Orphan item</li></div>

<!-- ❌ Table rows outside a table -->
<div><tr><td>Orphan cell</td></tr></div>

    Character references

    Three characters must be escaped in text content: &, < and (in attribute values) the quote character you are using. Everything else is optional but often clearer as a named reference.

    &amp;    →  &
&lt;     →  <
&gt;     →  >
&quot;   →  "
&#39;    →  '
&nbsp;   →  non-breaking space (glues words, does not collapse)
&copy;   →  ©
&mdash;  →  —
&rarr;   →  →
&hellip; →  …

<!-- Numeric references always work, even for characters with no name -->
&#x1F600;  →  😀
&#8212;   →  —

    Case, quotes, whitespace

    <!-- Tag names and attribute names are case-insensitive... -->
<P CLASS=lead>Legacy uppercase still parses.</P>

<!-- ...but lowercase is the universal convention. Attribute *values*
     are case-sensitive: "GET" ≠ "get" in some contexts. -->

<!-- Both quote styles are valid; double quotes are conventional -->
<img src="a.png" alt='Single quotes are fine too'>

<!-- Unquoted values work ONLY when there is no space or special char -->
<input type=text name=email>      <!-- valid -->
<input type=text name=my field>   <!-- ❌ breaks: use quotes -->

<!-- Whitespace collapses: all of these render identically -->
<p>One   two
   three</p>

<!-- ...unless you preserve it: -->
<pre>Line one
    indented line two</pre>
