    Accessibility & ARIA

    Native semantics first, ARIA second, and never the other way around.

    First rule of ARIA

    If you can use a native HTML element or attribute with the semantics and behaviour you require already built in, instead of re-purposing an element and adding an ARIA role, state or property to make it accessible, then do so.

    — W3C, ARIA in HTML
    <!-- ❌ ARIA-ified div instead of a native button -->
<div role="button" tabindex="0" onclick="submit()">Save</div>

<!-- ✅ Native button — keyboard, focus, Enter/Space, disabled
     state, form submission, and screen-reader announcement
     all handled by the browser. -->
<button type="submit">Save</button>

    Landmarks and structure

    • header, nav, main, aside, footer, form, search create landmarks.
    • Every page should have exactly one main.
    • Multiple landmarks of the same type need distinct aria-labels.
    • Landmarks are the primary way a screen-reader user skims a page — get them right before anything else.

    Accessible names priority

    How an element's accessible name is computed (highest priority first)
    PrioritySourceExample
    1aria-labelledbyaria-labelledby="heading-id"
    2aria-labelaria-label="Close dialog"
    3Native label association<label for>, <legend>, alt, <caption>
    4Element contentText inside a <button>
    5titleLast-resort tooltip text
    !

    Never rely on title alone — it is invisible to touch users and often truncated. Use aria-label or visible text.

    Live regions

    <!-- The region must exist in the DOM BEFORE you inject text. -->
<div id="status" aria-live="polite" aria-atomic="true"></div>

<script>
  document.getElementById("status").textContent =
    "Changes saved.";
</script>

<!-- polite: announced at the next pause (most messages).
     assertive: interrupts the user immediately (errors, alerts).
     role="alert" is shorthand for aria-live="assertive". -->

    Focus management

    • Never remove focus outlines. Style them, but keep them visible.
    • Use :focus-visible to show the outline only for keyboard users.
    • After closing a modal, return focus to the element that opened it.
    • tabindex="-1" makes an element programmatically focusable without adding it to the tab order.
    <style>
  /* Never do this: */
  /* * { outline: none; } */

  /* Do this instead: */
  :focus-visible {
    outline: 2px solid #0969da;
    outline-offset: 2px;
    border-radius: 4px;
  }
</style>

<main id="main" tabindex="-1"> … </main>
