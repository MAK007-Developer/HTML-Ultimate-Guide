    Quick Gotchas

    A symptom → cause lookup table for the bugs you will actually hit.

    Symptom → cause

    Twelve bugs and their causes
    SymptomLikely cause
    Layout collapses — everything stacks verticallyAn unclosed block element (div, p, section) swallowed its siblings.
    Everything after a <div /> disappears into the divHTML does not support self-closing syntax on non-void elements. Write <div></div>.
    Button submits the form when it shouldn'tMissing type="button". The default is submit.
    Form data arrives empty on the serverMissing name attribute on the input. Unnamed controls are never submitted.
    File uploads don't workMissing enctype="multipart/form-data" on the <form>.
    Opened tab can navigate the opener windowMissing rel="noopener" on a target="_blank" link.
    Layout shifts as images loadMissing width / height (or aspect-ratio) on the image.
    Autofill doesn't fill anythingMissing or wrong autocomplete tokens, or fields not wrapped in a <form>.
    Screen reader skips the error messageError text is not linked via aria-describedby and not announced via role="alert" or aria-live.
    Modal can't be closed with ESC or focus escapesCustom modal instead of <dialog> + showModal(). Native dialog gives you ESC, focus trapping and a backdrop for free.
    Anchor inside an anchor — the inner link does nothingNested <a> elements are invalid; the parser closes the outer link before opening the inner one. Never nest interactive content.
    :focus styles don't applyFocus was removed with outline: none, or the element isn't focusable (missing tabindex, or it's a div instead of a button). Use :focus-visible and native controls.
    ✔

    Bonus rule of thumb: when the browser “fixes” your markup, look at it in the DevTools Elements panel rather than your source file. The DOM shows what the parser actually built — which is what CSS, JS and assistive tech all see.
