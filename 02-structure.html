    02 · Structure

    Document Structure & Metadata

    The skeleton every page needs, the metadata that actually matters, and the one element you should probably never use.

    Minimal modern document

    <!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Page title — Site name</title>
  <meta name="description" content="A 150–160 character summary of this specific page.">
</head>
<body>
  <h1>Hello, world</h1>
</body>
</html>

    Non-negotiables

    • <!DOCTYPE html> as the very first thing — without it you get quirks mode.
    • lang on <html> — drives screen-reader pronunciation, hyphenation and translation.
    • <meta charset="utf-8"> within the first 1024 bytes.
    • Viewport meta — without it, mobile browsers render at a fake 980px width.
    • A unique, descriptive <title> — the single most important SEO string on the page.
    • Exactly one <h1> that matches the page's purpose.
    • Valid nesting — the parser will “fix” your mistakes in ways you won't like.

    Elements allowed in <head>

    Metadata content permitted inside <head>
    ElementPurpose
    titleDocument title (required, exactly one).
    metaCharacter set, viewport, description, robots, Open Graph, theme-color…
    linkStylesheets, icons, canonical, preload/preconnect, manifest, alternate.
    styleEmbedded CSS.
    scriptJavaScript (use defer, async or type="module").
    noscriptFallback markup when scripting is disabled.
    baseBase URL for relative links — use with extreme care.
    templateInert markup to be cloned later.

    Essential metadata

    <!-- ═══ SEO ═══ -->
<title>Responsive Images Explained — Acme Docs</title>
<meta name="description" content="How srcset, sizes and picture work, with copy-paste examples.">
<link rel="canonical" href="https://example.com/docs/responsive-images">

<!-- ═══ Open Graph (Facebook, LinkedIn, Slack, Discord…) ═══ -->
<meta property="og:type" content="article">
<meta property="og:title" content="Responsive Images Explained">
<meta property="og:description" content="How srcset, sizes and picture work.">
<meta property="og:image" content="https://example.com/og/responsive-images.png">
<meta property="og:image:width" content="1200">
<meta property="og:image:height" content="630">
<meta property="og:url" content="https://example.com/docs/responsive-images">
<meta property="og:site_name" content="Acme Docs">

<!-- ═══ Twitter / X cards ═══ -->
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:title" content="Responsive Images Explained">
<meta name="twitter:description" content="How srcset, sizes and picture work.">
<meta name="twitter:image" content="https://example.com/og/responsive-images.png">

<!-- ═══ Icons & PWA ═══ -->
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/icon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">  <!-- 180×180 -->
<link rel="manifest" href="/manifest.webmanifest">

<!-- ═══ Browser chrome colour (one per scheme) ═══ -->
<meta name="theme-color" content="#ffffff" media="(prefers-color-scheme: light)">
<meta name="theme-color" content="#0d1117" media="(prefers-color-scheme: dark)">

    The <base> warning

    <!-- ⚠️  Think twice. This changes the resolution of EVERY relative URL
        on the page: links, images, scripts, stylesheets, forms and even
        same-page "#fragment" links. -->
<base href="https://example.com/">

<!-- Only one <base> per document, and it must appear before any URL
     that it should affect. -->
<base target="_blank">   <!-- also sets a default for all links -->
    ✕

    Prefer absolute or root-relative paths over <base>. It is one of the most common causes of “works locally, 404s in production” bugs, and it silently breaks in-page anchors.
