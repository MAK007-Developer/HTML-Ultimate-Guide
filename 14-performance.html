    Performance-Oriented HTML

    Resource hints, script loading, and the HTML levers that move Core Web Vitals.

    Resource hints

    Hints and their cost / benefit
    HintWhen to useCostBenefit
    preconnectFonts, CDNs, API originsOne early connection per originSaves DNS + TLS on first request
    dns-prefetchFallback for browsers without preconnectDNS lookup onlySaves ~50ms on first request
    preloadCritical late-discovered resources (fonts, hero image, key CSS)High-priority fetchRemoves discovery latency
    prefetchNext-page navigationLow-priority fetchNear-instant navigation
    prerenderVery likely next pageFull page fetch + renderInstant navigation
    modulepreloadES modules used on the pageFetch + parse as moduleAvoids waterfall
     
    <!-- Preconnect to an origin you will definitely use -->
<link rel="preconnect" href="https://fonts.example.com" crossorigin>
<link rel="dns-prefetch" href="https://fonts.example.com">

<!-- Preload the LCP hero image -->
<link rel="preload" as="image"
      href="/img/hero.avif" type="image/avif"
      imagesrcset="/img/hero.avif 1x, /img/hero@2x.avif 2x"
      fetchpriority="high">

<!-- Preload a font — must include crossorigin -->
<link rel="preload" as="font" type="font/woff2"
      href="/fonts/inter.woff2" crossorigin>

    Preload rules

    • as is mandatory. A preload without as is ignored.
    • Fonts must include crossorigin — even same-origin fonts are fetched in CORS mode.
    • Preload only what the page will use in the first paint. Over-preloading starves critical resources.
    • Don't preload what the browser will discover anyway. Preload is for late-discovered resources — CSS background images, fonts referenced from CSS, JS-injected images.

    Script loading

    Script loading strategies
    StrategyDownloadExecutionUse when
    No attributeBlocks parsingImmediately when fetchedAlmost never — only for very tiny inline init.
    asyncParallelAs soon as fetched; may run out of orderIndependent third-party widgets (analytics).
    deferParallelAfter parsing, in document orderYour own app code — the default choice.
    type="module"Parallel (defer by default)After parsing, in orderAny modern ES module script.
     
    <!-- Default to defer for your own code. -->
<script src="/app.js" defer></script>

<!-- Module scripts defer automatically and also enforce order. -->
<script type="module" src="/app.mjs"></script>

<!-- Async is for independent, non-critical scripts. -->
<script async src="https://analytics.example.com/a.js"></script>

    Core Web Vitals HTML levers

    HTML changes that move each metric
    MetricHTML lever
    LCP — Largest Contentful PaintPreload the hero; do not lazy-load it; add fetchpriority="high"; serve modern formats (AVIF/WebP); use srcset to serve appropriately sized images.
    CLS — Cumulative Layout ShiftAlways set width + height on images and aspect-ratio on video; reserve space for ads and embeds; avoid inserting content above existing content.
    INP — Interaction to Next PaintBreak up long tasks in JS; use defer; avoid large inline scripts; avoid layout thrash in event handlers.

    noscript and progressive enhancement

    <!-- Provide a fallback for the ~1% who have JS disabled,
     and for the case where the script fails to load. -->
<noscript>
  <p>This page works without JavaScript, but the interactive demo
     needs it. <a href="/demo-static">See the static version</a>.</p>
</noscript>

<!-- Progressive enhancement: build the HTML first, layer JS on top. -->
<form action="/search" method="get">
  <input name="q" type="search" placeholder="Search…">
  <button type="submit">Search</button>
</form>
<!-- With JS, this form can be intercepted and results streamed in.
     Without JS, it submits normally. Either way, it works. -->
