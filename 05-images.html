    05 · Images

    Images & Responsive Images

    alt text rules, width/height, srcset, sizes, picture, figures, and the loading strategy that keeps Core Web Vitals green.

    Basics

    <img src="/img/cat.jpg"
     alt="A tabby cat asleep on a laptop keyboard"
     width="800"
     height="600"
     loading="lazy"
     decoding="async">
    • width + height are mandatory in practice: the browser reserves the correct aspect ratio before the image loads, which eliminates layout shift (CLS).
    • loading="lazy" defers off-screen images. Never use it on the LCP hero.
    • decoding="async" lets the browser decode off the main thread.
    • alt is required — even if it's alt="".

    alt text rules

    Choosing the right alt text
    Situationalt valueExample
    Informative imageDescribe the information, conciselyalt="Revenue grew 24% from 2024 to 2025"
    Purely decorativeEmpty string (still required!)alt=""
    Image inside a linkDescribe the destination, not the picture<a href="/"><img src="logo.svg" alt="Acme home"></a>
    Image with a visible captionDescribe the image; do not repeat the captionalt="The 2026 product line" + <figcaption>Figure 1: Product line</figcaption>
    Complex chart or diagramShort alt + a long description elsewherealt="Sales by region, 2026" + link to a data table
    Text rendered as an imageUse the exact text — or better, don'talt="50% off"

    srcset + sizes with w descriptors

    <img src="/img/hero-800.jpg"
     srcset="/img/hero-400.jpg   400w,
             /img/hero-800.jpg   800w,
             /img/hero-1200.jpg 1200w,
             /img/hero-1600.jpg 1600w"
     sizes="(min-width: 900px) 800px, 100vw"
     width="800" height="600"
     alt="Sunrise over the mountains"
     fetchpriority="high">

<!-- sizes tells the browser how wide the image will be RENDERED at
     each breakpoint. It multiplies by device pixel ratio to choose
     the best candidate. Without sizes, it assumes 100vw. -->

    srcset with x descriptors

    <!-- Fixed-size images (logos, icons) where you only care about DPR -->
<img src="/img/logo.png"
     srcset="/img/logo.png 1x, /img/logo@2x.png 2x, /img/logo@3x.png 3x"
     width="120" height="40"
     alt="Acme">

    picture for art direction and format negotiation

    <picture>
  <!-- Modern formats first; the browser picks the first it supports -->
  <source type="image/avif" srcset="/img/hero.avif 1x, /img/hero@2x.avif 2x">
  <source type="image/webp" srcset="/img/hero.webp 1x, /img/hero@2x.webp 2x">

  <!-- Art direction: a different crop on wide screens -->
  <source media="(min-width: 900px)" srcset="/img/hero-wide.jpg">
  <source media="(min-width: 480px)" srcset="/img/hero-square.jpg">

  <!-- Mandatory fallback — and the only element that carries alt -->
  <img src="/img/hero-narrow.jpg" width="800" height="600"
       alt="Sunrise over the mountains">
</picture>
    ✔

    Use <picture> when you need different crops or formats. Use srcset + sizes when you need the same image at different resolutions.

    figure / figcaption

    <figure>
  <img src="/img/revenue.png"
       alt="Bar chart: revenue rose 24% from 2024 to 2025."
       width="640" height="400">
  <figcaption>Figure 1. Annual revenue, 2024–2025.</figcaption>
</figure>

<!-- <figure> isn't only for images: code, tables, quotes all work -->
<figure>
  <pre><code>npm install</code></pre>
  <figcaption>Installing the package.</figcaption>
</figure>

    Loading strategy

    Choosing loading, fetchpriority and decoding
    AttributeValueUse forAvoid
    loadinglazyBelow-the-fold imagesThe LCP hero image
    loadingeagerThe hero / above-the-fold imagesLong lists of thumbnails
    fetchpriorityhighThe single LCP imageMany images at once
    fetchprioritylowDecorative or below-fold artThe hero
    decodingasyncMost imagesImages that must be pixel-perfect at first paint
    decodingsyncRarely — blocks renderingAnything large
    ✕

    Never lazy-load the LCP hero image. loading="lazy" delays the request until layout is known, which can add hundreds of milliseconds to Largest Contentful Paint. The hero should be loading="eager" (the default) with fetchpriority="high", and ideally preloaded.
